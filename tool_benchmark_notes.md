# Founder Tool Benchmark Notes

## Scope

This working note records external patterns reviewed for improving ASaaSI’s founder assessment and practical workbenches. The objective is to borrow useful interaction and outcome patterns, not competitor copy, scores, or visual language.

| Product | Observed assessment pattern | Useful ASaaSI adaptation | Source |
|---|---|---|---|
| Founder Institute Entrepreneur DNA Assessment | A time-bounded assessment presents a report preview, compares traits against a large applicant benchmark, and connects assessment data to mentor, peer, and later company-performance feedback. | ASaaSI should show **what is assessed**, return a clear stage-and-function profile, and connect every result to a relevant roadmap move, person, event, or practice rather than claiming predictive accuracy. | [Founder Institute Entrepreneur DNA Assessment](https://fi.co/dna) |
| The Brutally Honest Mentor Startup Assessment | Independent co-founder input is synthesized into readiness dimensions, team-alignment signals, benchmark comparisons, and a next-action report. The product makes the score legible through named dimensions and explicit action steps. | ASaaSI should emphasize **decision evidence and alignment**, use transparent labelled signals rather than opaque scores, allow a founder to compare current constraints across key functions, and turn a result into one bounded next experiment. | [The Brutally Honest Mentor Assessment](https://brutallyhonestmentor.com/assessment) |
| Strategyzer Testing Business Ideas | The method turns a business idea into prioritised, testable assumptions; pairs the largest risk with an experiment; and uses the resulting evidence to adapt the plan. It offers an experiment library organised by cost, time, and strength of evidence. | Every ASaaSI workbench should end with one explicit **assumption → test → evidence → decision** record. The interface should help founders select a modest experiment and declare what evidence would change the next move. | [Strategyzer, Testing Business Ideas](https://www.strategyzer.com/library/testing-business-ideas-book) |
| Canvanizer Lean Canvas | A concise collaborative canvas creates a shared record across problem, solution, unique value proposition, metrics, advantage, channels, costs, and revenue. It keeps the business model editable and visible as a single decision surface. | ASaaSI should use compact, stage-aware decision records rather than a generic empty canvas. A workbench should preserve only the fields relevant to the founder’s current constraint and connect them to a saved evidence note. | [Canvanizer Lean Canvas](https://canvanizer.com/new/lean-canvas) |

## Design and Product Implications

ASaaSI will retain its editorial operating-system language: no broad scorecard, generic gauge, or decorative dashboard. The assessment should operate as a **Founder Signal Record**: the founder names the live constraint, records evidence, receives a bounded readiness readout, and is routed to one next useful action. Each practical workbench should close with an **assumption → test → evidence → decision** record. A future team mode may add separate responses and an alignment readout, but it must remain clearly labelled as a contextual working aid rather than a predictive or investment-readiness claim.

## Implemented in This Pass

The public founder assessment now begins as a connected **Constraint → Evidence → Next Move** record rather than a generic multiple-choice quiz. Its first screen names the assessment method, makes the current decision state visible, and generates one bounded experiment record when completed. The result deliberately avoids readiness scoring or predictive claims, while offering a direct next workbench or a saved founder record.

Protected Pricing, SaaS Health, Runway, Market Map, and Knowledge routes now preserve their own operating path through sign-in. Each path names the working object that will be restored after identity confirmation: Buyer → Value → Price, Signal → Diagnosis → Next Test, Cash → Net Burn → Scenario, Customer → Evidence → Test, or Claim → Evidence → Practice. Tablet access screens now stack the route-specific navy record above the identity form so the evidence path remains readable.
