# Weekly Rule Application and Evidence Move Cycle

## External findings

Maze describes continuous discovery as a habitual practice of weekly customer insight gathering across the product lifecycle, rather than a one-time pre-delivery stage.[1] This supports a repeatable weekly evidence move tied to a current decision, not a static research archive.

Miro describes continuous discovery as frequent small research activities that validate assumptions early and close the loop by feeding learning back into prioritization and decisions. It also highlights preserving evolving understanding across sessions rather than isolating one insight.[2]

## ASaaSI implication

ASaaSI should make a founder-authored working rule usable in the next weekly cycle without treating it as a permanent truth. The next handoff should preserve the rule’s source outcome and scope, then ask the founder to name one fresh evidence move, buyer context, and response condition that could confirm, revise, or retire the rule. It should remain attached to the original retained record and recover directly into Customer Evidence or Weekly Review.

## ASaaSI audit and selected scope

Weekly Review already creates a dated research cadence for the active primary bet and carries it into Customer Evidence. Knowledge already retains a founder-authored claim, scope, and next evidence move on the original source record. The missing handoff is that a saved field-guide rule cannot currently travel with the weekly research cadence, so its source, boundary, and revision condition disappear exactly when the founder opens a fresh customer test.

The selected enhancement is a bilingual **Weekly Rule Application** context inside the existing research cadence. It appears only when the primary bet has a saved Knowledge guide. The founder must consciously include that guide in the weekly move, then still write a fresh focused question, buyer context, due date, and response rule. The saved cadence retains the guide source, claim, scope, and proposed next evidence move. Customer Evidence shows this as reference context only and requires all new factual test fields. It will not auto-fill, copy an outcome, or imply that a working rule is true.

## Implementation and validation notes

Weekly Review now exposes an optional Reversible Field Guide context only when the active primary bet has retained Knowledge guidance. The founder consciously opts it into the weekly cadence, then writes a fresh question, buyer context, due date, and response rule. The cadence stores rule source, claim, scope, and prior revision move, and Customer Evidence renders these as reference-only context while requiring a new concrete moment, trigger, workaround, quote, success condition, action, and response rule.

TypeScript and production builds pass. Desktop and 375px Arabic RTL protected views were checked after route-specific refinement. The visual review’s route-differentiation guidance was applied: Weekly Review now reads as a vertical decision-return ledger, while Customer Evidence remains an assumption-language-commitment loop. The request for circular nodes or rings was rejected because it conflicts with ASaaSI’s explicit no-circle rule; fine blue-grey rules, saffron current-step markers, and sequenced ledger fields carry the state grammar.
